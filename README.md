# LinkVault — версия с аккаунтами и облачной библиотекой

Проект сохраняет исходный интерфейс LinkVault и добавляет регистрацию по email, вход, подтверждение почты, восстановление пароля, TOTP-двухфакторную защиту, облачную синхронизацию ссылок и административную статистику.

## Состав проекта

- `index.html`, `style.css`, `app.js`, `links.js`, `search.js`, `storage.js` — интерфейс и библиотека ссылок.
- `auth.js` — регистрация, вход, восстановление пароля, MFA и панель администратора.
- `supabase-config.js` — публичный URL проекта и publishable/anon key.
- `supabase-schema.sql` — таблицы, RLS-политики, триггер профиля и защищённая функция статистики.

## 1. Создать Supabase-проект

1. Открой https://supabase.com/ и создай проект.
2. В Project Settings → API скопируй Project URL и publishable key (или legacy anon key).
3. Открой `supabase-config.js` и замени `ВСТАВЬТЕ_PROJECT_URL` и `ВСТАВЬТЕ_PUBLISHABLE_OR_ANON_KEY` своими значениями.
4. Никогда не вставляй в этот файл `service_role` / secret key. Его нельзя публиковать в браузерном коде.

## 2. Создать таблицы и включить защиту

1. В Supabase открой SQL Editor → New query.
2. Скопируй весь `supabase-schema.sql` и выполни запрос.
3. В Table Editor проверь, что создались `profiles`, `linkvault_links`, `user_categories`, `admin_users`.
4. Убедись, что RLS включён на всех этих таблицах. Политики из SQL ограничивают чтение и изменение ссылок только владельцем.

## 3. Настроить подтверждение почты и адреса возврата

1. В Supabase открой Authentication → URL Configuration.
2. В Site URL укажи опубликованный адрес сайта, например `https://USERNAME.github.io/LinkVault/`.
3. В Redirect URLs добавь этот же адрес и адрес локальной разработки, если будешь тестировать локально.
4. В Authentication → Providers → Email оставь включённое подтверждение email.
5. Настрой SMTP для надёжной отправки писем, если стандартная отправка Supabase не подходит для публичного запуска.

## 4. Опубликовать на GitHub Pages

1. Загрузить все файлы архива в корень репозитория (включая `auth.js`, `supabase-config.js`, `supabase-schema.sql`).
2. Нажать Commit changes и дождаться публикации GitHub Pages.
3. Открыть сайт и проверить регистрацию с отдельным тестовым адресом.
4. Проверь письмо подтверждения, выход, повторный вход и восстановление пароля.

## 5. Назначить себя администратором

1. Зарегистрируй свой аккаунт на опубликованном сайте и подтверди почту.
2. В Supabase открой Authentication → Users и скопируй UUID своего пользователя (не email).
3. В SQL Editor выполни запрос, заменив UUID на свой:

```sql
insert into public.admin_users (user_id)
values ('ВСТАВЬ-СЮДА-UUID-СВОЕГО-АККАУНТА')
on conflict (user_id) do nothing;
```

4. Выйди и войди на сайте заново. В меню аккаунта появится LinkVault Admin. Панель получает агрегированную статистику через RPC, а не открывает список пользователей.

## 6. Двухфакторная защита

После входа открой меню аккаунта → «Настроить двухфакторную защиту». Отсканируй QR-код в совместимом приложении-аутентификаторе и введи текущий шестизначный код. При последующих входах понадобится второй фактор.

Важно: не теряй доступ к приложению-аутентификатору. В этой версии не реализованы резервные коды и управление всеми активными сессиями.

## 7. Что хранится

Хранятся только названия ссылок, URL, описания, категории, избранное и дата создания. Пароли от сторонних сайтов не сохраняются. Пароли аккаунтов LinkVault обрабатывает Supabase Auth; приложение не записывает их в свою таблицу.

## Важные ограничения перед публичным запуском

- Владелец Supabase-проекта должен самостоятельно контролировать настройки, биллинг, SMTP, лимиты и резервное копирование.
- Административная панель показывает агрегаты: общее число аккаунтов, подтверждённые аккаунты, регистрации за 7 дней и число ссылок. Она не показывает email пользователей.
- TOTP MFA включается пользователем добровольно; пока он не включён, аккаунт защищён паролем и механизмами Supabase Auth.
- Перед приглашением других пользователей протестируй RLS под двумя разными аккаунтами и убедись, что один аккаунт не может прочитать ссылки другого.
- Не публикуй скриншоты/логи с токенами, паролями, QR-секретами или ключами.
- Если у тебя уже были ссылки в LocalStorage, при первом входе сайт предложит перенести их в облако. Подтверждай перенос только в своём личном браузере.
